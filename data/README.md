# Данные сайта

## Каталог

| Файл | Что внутри |
| --- | --- |
| `units.json` | юниты |
| `buildings.json` | строения |
| `factions.json` | фракции (цвет, эмблема, лор, сильные/слабые стороны) |
| `tags.json` | реестр тегов каталога |

- Формат и все поля описаны в самом верху каждого файла — в блоке `_schema`. Пример юнита там же.
- Картинка подставляется автоматически по `id`: `assets/img/catalog/<id>.webp`. Переопределить можно полем `image`, а `"image": ""` показывает инициалы. Подходящего id нет — карточка честно покажет инициалы.
- Теги: сначала добавьте запись в `tags.json`, затем впишите её `id` в поле `tags` карточки. Незнакомый тег всё равно покажется — просто как есть.
- Полосы характеристик (прочность, щит, урон, скорость, дальность) считаются автоматически по общей шкале всех юнитов и строений — задавать максимумы вручную не нужно.
- Цифры статистики на главной («178 юнитов и строений», «2 фракции» и т.д.) лежат в `assets/js/site-config.js` (`stats`).

## Структура вики: `wiki-nav.json`

- `categories` — разделы бокового меню и главной вики.
  - `id` — идентификатор раздела;
  - `icon` — одна из иконок: `book`, `shield`, `cube`, `gear`, `compass`, `users`, `clock`;
  - `title`, `desc` — подписи `{ ru, en }`;
  - `articles` — статьи раздела по порядку.
- `articles` — записи вида `{ "slug": "lore/overview", "title": {…}, "desc": {…} }`.
  - `slug` — путь к файлу без `content/<язык>/` и без `.md` (файл должен существовать в `content/ru/` и `content/en/`).

Как создать и оформить саму статью — см. `../content/README.md`.
